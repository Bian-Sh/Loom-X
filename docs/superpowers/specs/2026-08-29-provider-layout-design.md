# Provider 布局对齐设计

## 1. 目标

将 Avalonia 桌面端的整体壳和 Provider 页面布局对齐 `.design/pages/providers/index.html` 原型的空间层级与信息分组。当前阶段只对齐布局结构、控件分组和响应式排列，不调整配色，也不嵌入 HTML。

## 2. 现状与约束

- 桌面端使用 `MainWindow.axaml` 作为左侧导航和内容容器。
- Provider 业务状态集中在 `ProvidersViewModel`，已有 Provider/模型列表、选择、刷新、新增、删除、自动保存和连接测试命令。
- Avalonia 页面必须继续使用现有 ViewModel 绑定，不在视图中复制配置读写或请求逻辑。
- 当前窗口最小尺寸为 920x600，布局必须在该尺寸下可滚动且不发生内容遮挡。
- 用户明确暂不要求配色像素级一致，因此本次不迁移原型 CSS 色值。

## 3. 目标布局

### 3.1 桌面壳

`MainWindow.axaml` 调整为两列结构：左侧固定导航栏，右侧为主区域。主区域顶部只承载当前页面标题和说明，移除旧版面包屑与常驻状态徽标，下面使用 `ContentControl` 承载当前页面。导航项保留现有六个页面和命令，并显示当前项高亮及分组标签，Provider 页面仍通过 `CurrentView` 切换。

### 3.2 Provider 页面

`ProvidersView.axaml` 使用纵向滚动内容，顶部标题由桌面壳提供，页面内部层级固定为：

1. 四个摘要块：Provider 数量、可用模型数量、受保护密钥数量、连接健康状态。
2. 工作区两列：左侧 Provider 目录，右侧 Provider 编辑器。

左侧目录包含目录标题/数量、新增图标按钮、搜索框和 Provider 列表项。列表项按原型顺序展示标识、名称、状态点、Base URL、协议、模型数量、密钥状态和开关控件，并继续绑定 `Providers` 与 `SelectedProvider`。

右侧编辑器包含选中 Provider 标题、辅助说明、图标删除操作和三项标签；不再显示旧版页面内刷新/新增文字操作：

- `基础`：显示名称、Provider ID/业务 ID、Provider 类型、Base URL。
- `请求`：协议选择、API Key 状态与清除操作、可选 Headers、连接测试状态和按钮。
- `模型`：模型搜索、添加/同步操作和表格化模型列表（拖拽位、模型标识、能力、上下文、远程状态、启用开关）。旧版模型长表单不放在主列表视图中。

标签切换只影响可见面板，不改变现有 ViewModel 状态；当前选中 Provider 或模型在切换标签后保持不变。

### 3.3 响应式排列

- 宽窗口：目录宽度约 270-340px，编辑器占用剩余空间。
- 中等宽度：工作区退化为上下排列，Provider 列表横向压缩为多列或紧凑列表，摘要块改为两列。
- 窄窗口：导航栏隐藏为顶部入口，表单改为单列，模型表格隐藏次要列并保留模型名、能力和启用状态。

Avalonia 中优先使用 `Grid`、`ScrollViewer`、`WrapPanel` 和 `TabControl` 实现，不引入新的 UI 框架或 WebView。

## 4. ViewModel 补充

仅在视图无法直接计算时补充只读展示属性：可用模型总数、已配置密钥数量、健康 Provider 数量/总数，以及当前编辑标签。统计值随 `Providers`、Provider 启用状态和模型集合变化刷新；不改变配置接口和持久化格式。

## 5. 数据流与错误处理

- Provider 目录和摘要由 `ProvidersViewModel.RefreshAsync` 加载的同一份集合驱动。
- 现有自动保存继续处理编辑字段变更，布局调整不新增第二套保存机制。
- 连接测试、保存、删除失败信息继续显示在现有 `Status`/`ConnectionStatus` 区域，视图只负责放置位置和滚动行为。
- 没有选中 Provider 或模型时，对应编辑区域显示空状态，按钮按现有命令可执行性处理。

## 6. 验证

- `dotnet build OllamaHub.slnx`
- `dotnet test`
- 启动桌面端，在 1180x760、920x600 和窄窗口尺寸下检查：导航、摘要、目录、标签、表单和模型列表均可见且可滚动；窗口缩放不导致重叠。
- 手动确认现有 Provider 选择、刷新、新增、自动保存、连接测试、模型保存/删除命令仍然可用。

## 7. 非目标

- 不迁移原型颜色、阴影、字体文件或 CSS。
- 不实现原型中尚未存在于当前 ViewModel 的远程模型差异抽屉等新业务能力；同步按钮保留原型位置，后续接入远程同步命令。
- 不修改网关核心、数据库结构或 HTTP API。
