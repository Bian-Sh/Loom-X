# 磨砂程度单向语义与算法行移除设计

## 背景

设置页当前仍显示只读的“磨砂算法 / Acrylic（亚克力）”整行，用户无法从中获得可操作信息。磨砂滑块此前使用带负值的范围并只改变窗口背景遮罩 Alpha，系统 Acrylic 材质仍持续参与渲染，低值无法稳定呈现通透状态。

## 目标

- 删除设置页底部“磨砂算法”整行，不再展示当前算法名称。
- 将“磨砂程度”定义为单向参数：数值越低越通透，数值越高越模糊。
- 将滑块和配置校验统一为 `0..200`，保留默认值 `24`。
- 低值优先使用 `Transparent`，高值优先使用 `AcrylicBlur`，并让背景遮罩 Alpha 随数值平滑递增。
- 保留旧配置字段和旧调用参数，旧算法值继续归一为 Acrylic，不改变数据库结构。

## 非目标

- 不新增材质算法或数据库迁移。
- 不改变透明程度滑块的 `0..100` 语义。
- 不重构设置页导航、主题资源或其他外观参数。

## 交互与运行时行为

| 磨砂值 | 用户语义 | 材质优先级 | 背景遮罩 |
| --- | --- | --- | --- |
| `0` | 最通透 | `Transparent -> AcrylicBlur` | 最低基底，接近完全透明 |
| `1..99` | 通透到中等 | `Transparent -> AcrylicBlur` | 随值平滑增加 |
| `100..200` | 中等到最强磨砂 | `AcrylicBlur -> Transparent` | 随值平滑增加 |

窗口仍在透明开启时使用透明背景，透明关闭时使用不透明副本。窗口材质优先级仅由磨砂值决定；传入的 `algorithm` 参数继续保留以兼容现有调用方，但运行时固定归一为 Acrylic。

旧配置中的负磨砂值在配置加载和保存边界归一到 `0`，超过 `200` 的值归一到 `200`，避免旧数据让滑块越界。配置验证拒绝范围外的新输入。

## 实现边界

- `SettingsView.axaml`：删除算法整行，将磨砂滑块改为 `Minimum="0" Maximum="200"`，提示文案同步为单向语义。
- `MainWindow.axaml.cs`：集中定义磨砂边界和透明材质阈值；按磨砂值计算遮罩 Alpha，并生成低值/高值对应的 `TransparencyLevelHint`。
- `ConfigurationManagementService` 及设置映射：统一使用 `0..200` 验证和边界归一，保留 `TransparencyAlgorithm` 的 Acrylic 兼容逻辑。
- 现有设置页、配置服务和窗口外观契约测试：覆盖控件移除、范围约束、单调 Alpha、材质优先级和旧值兼容。

## 验证策略

1. 运行设置页与配置相关的定向测试，确认无算法行、范围和边界归一正确。
2. 运行完整 `OllamaHub.Tests` 测试集。
3. 以 Release 配置发布桌面端，检查发布包可启动并在设置页验证滑块两端及中点的视觉顺序。
4. 执行 `git diff --check`，确保没有格式错误。
