# 透明度与颗粒晕开度分离设计

## 背景

设置页此前显示只读的“磨砂算法 / Acrylic（亚克力）”整行，且透明度与磨砂滑块共同计算表面 Alpha。结果是透明度变化被磨砂值压缩，磨砂值在 `100` 前后还会切换材质优先级，用户看到的是突然变得不透明而不是连续的磨砂变化。

## 目标

- 删除设置页底部“磨砂算法”整行，不再展示当前算法名称。
- 将透明度和颗粒晕开度定义为两个独立参数：透明度控制表面 Alpha，Blur 控制独立磨砂遮罩。
- 将 Blur 定义为单向参数：数值越低越通透，数值越高越模糊。
- 透明度保持 `0..100`，Blur 保持 `0..200`，保留默认值 `24`。
- 全部 Blur 值固定使用 `AcrylicBlur -> Transparent`，遮罩强度随 Blur 平滑递增，不在 `100` 处切换材质。
- 保留旧配置字段和旧调用参数，旧算法值继续归一为 Acrylic，不改变数据库结构。

## 非目标

- 不新增材质算法或数据库迁移。
- 不重构设置页导航、主题资源或其他外观参数。

## 交互与运行时行为

| 参数 | 范围 | 用户语义 | 运行时作用 |
| --- | --- | --- | --- |
| 透明度 | `0..100` | 数值越低越透明，越高越不透明 | 只修改窗口背景、玻璃层和弹窗表面的 Alpha |
| 颗粒晕开度（Blur） | `0..200` | 数值越低越通透，越高越模糊 | 只修改独立磨砂遮罩的强度，`0/100/200` 连续递增 |

窗口仍在透明开启时使用透明背景，透明关闭时使用不透明副本。窗口材质优先级固定为 `AcrylicBlur -> Transparent`；传入的 `algorithm` 参数继续保留以兼容现有调用方，但运行时固定归一为 Acrylic。

旧配置中的负磨砂值在配置加载和保存边界归一到 `0`，超过 `200` 的值归一到 `200`，避免旧数据让滑块越界。配置验证拒绝范围外的新输入。

## 实现边界

- `SettingsView.axaml`：删除算法整行，将磨砂滑块改为 `Minimum="0" Maximum="200"`，提示文案同步为单向语义。
- `MainWindow.axaml.cs`：集中定义磨砂边界；透明度单独计算表面 Alpha，Blur 单独计算遮罩 Alpha，并始终生成同一组 `TransparencyLevelHint`。
- `WindowAppearanceCoordinator`：同步主窗口和独立弹窗的透明度表面与磨砂遮罩，保证两个参数不会相互覆盖。
- `VisualTokens.axaml` 及窗口 XAML：增加独立 `BlurOverlayBrush` 层，放在背景与内容之间，不拦截输入。
- `ConfigurationManagementService` 及设置映射：统一使用 `0..200` 验证和边界归一，保留 `TransparencyAlgorithm` 的 Acrylic 兼容逻辑。
- 现有设置页、配置服务和窗口外观契约测试：覆盖控件移除、范围约束、单调 Alpha、材质优先级和旧值兼容。

## 验证策略

1. 运行设置页与配置相关的定向测试，确认无算法行、范围和边界归一正确。
2. 运行完整 `OllamaHub.Tests` 测试集。
3. 以 Release 配置发布桌面端，检查发布包可启动，在设置页验证透明度和 Blur 的 UIA 写入、回显及滑块两端与中点的视觉顺序。
4. 执行 `git diff --check`，确保没有格式错误。
