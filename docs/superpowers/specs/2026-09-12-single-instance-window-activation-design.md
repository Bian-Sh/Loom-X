# LoomX 单实例重复启动激活设计

## 背景

LoomX 当前使用 `Local\\LoomX` 互斥锁保证桌面端单实例。重复启动时，后续进程只记录告警并退出，用户看不到已有窗口，因此容易误以为应用没有启动。

## 目标

- 重复启动 LoomX 时激活已有实例的窗口。
- 已有窗口最小化时先恢复为普通状态。
- Windows 上尽可能将已有窗口置于前台；其他 Avalonia 平台使用标准窗口激活能力。
- 保持单实例约束，不让第二个进程初始化配置库或网关。
- 激活通信失败时后续进程仍快速退出，并记录不包含敏感数据的结构化告警。

## 方案

首实例在完成单实例互斥后启动一个用户会话内的命名管道监听器。监听器只接受固定的 `activate` 命令，不传递启动参数、配置内容或用户数据。

后续实例获取不到单实例互斥时，以短超时向该命名管道发送一次激活请求；必要时进行少量短间隔重试，随后退出。首实例收到请求后通过 UI 调度器调用主窗口激活逻辑：恢复最小化状态、调用 Avalonia `Activate()`，Windows 平台通过窗口句柄调用 `ShowWindow(SW_RESTORE)` 和 `SetForegroundWindow`。激活逻辑保持幂等，窗口已经在前台时不改变其状态。

通信监听器随 `App` 生命周期启动和释放，管道异常只影响重复启动提示，不影响首实例正常运行。日志记录请求是否发送、是否激活和进程标识，不记录管道正文以外的任何用户数据。

## 测试

- 为激活命令解析、重复启动发送行为和失败降级增加单元测试。
- 保留现有单实例策略测试，确认 `--allow-multiple-instances` 调试开关不受影响。
- 发布 `win-x64` 包后启动首实例，再启动同一包第二次，验证第二次启动后首窗口从最小化状态恢复并成为前台窗口；检查日志仅包含安全摘要。

## 非目标

- 不改变配置数据库路径、网关生命周期或多实例调试开关。
- 不通过窗口标题或进程枚举猜测目标实例。
