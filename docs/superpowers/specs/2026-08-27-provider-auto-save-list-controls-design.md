# Provider 自动保存与列表控制设计

## 目标

精简 Provider 管理页的新增、启停和保存操作，使高频操作集中在左侧目录，并将编辑器改为自动保存。

## 交互规则

- 移除页面顶栏的“新增 Provider”按钮。
- Provider 目录标题右侧不再显示数量，改为 `+` 图标按钮。
- 点击 `+` 后创建并选中一个新的 Provider 草稿，编辑器显示默认空白配置，并用 toast 提示。
- Provider 卡片的连接状态不再使用文字 badge；在 Provider 名称后显示实心状态圆点，绿色表示正常，黄色表示待验证。
- Provider 卡片右侧显示启用开关；切换后立即自动保存，并用 toast 提示启用或停用结果。
- 编辑器“基础”页不再显示“启用 Provider”配置行。
- 删除编辑器底部的“撤销”“保存 Provider”按钮和保存状态栏。
- 文本框与下拉框修改后防抖自动保存；有效配置写入后用 toast 提示已保存到 `OllamaHub.db`。
- Base URL 等校验失败时不显示成功提示，而是用 toast 提示需要修正的字段。

## 数据与显示

- Provider 列表继续由页面内现有演示数据渲染，不引入新依赖或持久化层。
- 新增草稿使用唯一的演示 ID，避免与现有 Provider 冲突。
- 自动保存只更新当前原型运行状态，不改变其他页面或真实后端。

## 验证标准

- 页面中不存在顶栏新增按钮、数量 badge、状态文字 badge、编辑区启用行、撤销按钮和保存按钮。
- `+` 可以新增并选中 Provider 草稿。
- 每张 Provider 卡片的状态圆点紧跟名称，启用开关位于卡片右侧。
- 表单修改与启用切换均产生正确的 toast 反馈。
- `.design/scripts/validate.ps1` 校验通过。
