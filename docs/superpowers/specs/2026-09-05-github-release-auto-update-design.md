# LoomX GitHub Release 自动更新设计

## 目标

为 Windows 桌面端补齐基于 GitHub Release 的更新体验，参考 AionUI 的交互形态：启动或运行期间发现新版本时，在主窗口右下角显示更新通知卡片；用户可以查看更新日志，并通过一次“立即下载”完成下载、校验、安装和重启。

本次只支持稳定版 Release，不提供预览渠道。更新载体沿用现有 Inno Setup 安装包，不新增独立 updater 可执行文件。

## 用户流程

### 启动检查

应用完成配置初始化并显示主窗口后，若“自动检查更新”已启用，则在后台执行一次稳定版检查。检查不阻塞主窗口启动，也不自动下载或安装。发现更高版本后显示右下角更新卡片；没有更新或检查失败时不弹出打扰性卡片，仅记录状态和日志。

### 运行期间定时检查

自动检查启用时，应用启动后每 24 小时执行一次检查。定时检查与启动检查使用相同的稳定版查询和卡片状态；发现更新只提示用户，不在后台静默替换程序。应用退出时取消定时器，不写入额外的更新数据库状态。

### 设置页手动检查

设置 → 更新页保留“检查更新”按钮。用户点击后立即执行检查，并在页面状态中显示“正在检查”“已是最新版本”或错误摘要。发现更新时同时显示右下角卡片，用户可从卡片查看日志并开始更新。手动检查不受上一次定时检查结果影响。

### 通知卡片与更新日志

卡片固定在主窗口右下角，至少包含：下载图标、当前版本到新版本的对比、更新日志链接、“稍后”和“立即下载”。

卡片状态包括：检查中、发现新版本、正在下载、校验中、正在安装、错误。下载状态显示进度百分比、已下载/总大小和速度；关闭或稍后只隐藏卡片，不取消正在进行的下载。

“更新日志”打开居中的模态窗口，窗口内容可滚动，安全渲染 GitHub Release 的 Markdown 子集（标题、段落、列表和链接文本），不执行 HTML 或脚本。无日志时显示明确的暂无说明。

用户点击“立即下载”后，流程自动执行：下载安装器和 SHA-256 校验文件 → 校验摘要 → 启动 Inno Setup 静默安装 → 由安装器关闭当前 LoomX、覆盖安装并重新启动。下载或校验失败时保留主窗口并显示可重试错误，不启动安装器。

## 组件与数据流

### UpdateService

新增可注入的 `UpdateService`，负责网络和更新流程，不直接依赖 Avalonia 控件：

- 查询 `https://api.github.com/repos/Bian-Sh/Loom-X/releases`，过滤 `draft` 和 `prerelease`，按 SemVer 选择最高稳定版本。
- 验证 tag 格式 `vMAJOR.MINOR.PATCH`，并与构建时注入的当前版本比较。
- 选择 Windows x64 的 `LoomX-<version>-setup.exe` 及同名 `.sha256` 资产；资产缺失或配对不一致视为不可安装。
- 使用流式下载报告进度，文件保存到 `%TEMP%\LoomX\updates\<version>`，避免写入配置目录。
- 读取校验文件中的十六进制摘要并使用 SHA-256 验证安装器；不记录下载 URL、文件正文或校验内容到业务日志。
- 启动安装器时使用 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`。安装器配置改为 `RestartApplications=yes`，让 Inno Setup 接管关闭和重启当前应用。

`UpdateService` 通过接口接收 `HttpClient`、时间提供器和安装器启动器，测试可以替换这些依赖，不执行真实进程。

### 更新协调与 ViewModel

新增共享的更新状态协调器/ViewModel，供 `MainWindow` 右下角卡片和 `SettingsViewModel` 使用。协调器保证检查和下载单飞：启动检查、定时检查或手动检查重叠时只保留一个网络请求；下载期间新的检查不会覆盖下载状态。

更新状态至少包含当前版本、目标版本、Release 页面地址、Release notes、阶段、进度、错误摘要和是否有可用更新。UI 层只消费状态和命令，所有网络、文件和进程操作都在服务层完成。

### 代理设置

`AppSettings` 新增 `UseProxyForUpdates` 布尔字段，默认值为 `true`，旧数据库迁移时使用同样的默认值。设置页更新 Tab 增加“更新时使用代理”复选框，并自动保存。

- 复选框关闭：更新请求直连。
- 复选框开启：沿用现有代理模式；`direct` 使用直连，`system` 使用系统代理，`custom` 使用已配置的地址、端口和凭据。

更新请求不复用 Provider 的 API Key 或自定义 Header。代理密码只传给 `WebProxy`，不进入日志、诊断摘要或错误文本。

### 版本注入

项目文件提供当前默认版本，发布流水线从 `github.ref_name` 去掉 `v` 后通过 MSBuild `Version` 属性注入。应用从自身程序集的 informational version 读取版本，并去掉构建元数据后用于显示和 SemVer 比较，消除 `SettingsViewModel` 的硬编码版本。

## GitHub Release 约定

现有发布工作流继续生成：

- `LoomX-<version>-setup.exe`
- `LoomX-<version>-setup.exe.sha256`

更新服务只接受 HTTPS 和 GitHub 官方 Release/API 域名，手动处理重定向时限制跳转次数并逐跳校验主机。Release API 错误、无稳定 Release、资产缺失、版本非法和摘要不匹配都转为用户可见的安全错误摘要，并记录结构化日志（Provider/版本/状态码/字节数/耗时等）。

## 错误与恢复

- 检查超时或网络不可用：设置页显示失败状态，启动/定时检查静默记录；手动检查提供重试。
- 找到版本但没有兼容安装器：卡片显示无法自动安装，可打开 Release 页面。
- 下载中断：保留错误状态和重试命令，清理不完整临时文件。
- SHA-256 不匹配：删除下载文件，阻止安装并记录校验失败。
- 安装器启动失败：主窗口保持运行，显示安装启动失败；不伪造成功状态。
- 安装器关闭或重启失败：由 Inno Setup 日志定位，应用下次启动仍可再次检查。

## 测试策略

### 自动化测试

- SemVer 解析、稳定版过滤和最高版本选择。
- Windows 安装器与 `.sha256` 资产配对、非法 URL/重定向和摘要校验。
- 代理开关对 `HttpClientHandler` 的影响，默认值和旧数据库迁移。
- 检查/下载/校验/安装状态机的单飞、取消、重试和错误转移。
- 更新卡片、更新日志弹窗、设置页手动检查按钮和“无预览渠道”UI 契约。
- 日志安全测试，确认 API Key、代理密码、请求/响应正文和下载内容不进入日志。

### 真实发布烟测

1. 构建并安装当前版本到 `%LOCALAPPDATA%\Programs\LoomX`。
2. 推送临时稳定 tag（例如 `v0.12.7`），等待现有 GitHub Actions 生成 Release 和安装器资产。
3. 启动旧版本，验证启动卡片、更新日志、手动检查和定时检查入口。
4. 点击“立即下载”，验证进度、SHA-256 校验、Inno Setup 覆盖安装和自动重启，确认新版本号。
5. 用 `gh release delete v0.12.7 --yes --cleanup-tag` 删除临时 Release 和 tag，并保留本地日志作为验证记录。

## 取舍

方案 A 复用现有安装器和 Inno Setup 的 Restart Manager 能力，新增代码集中在更新服务、状态协调和 UI。独立 updater helper 作为后续故障兜底，不在本次引入；若真实安装烟测证明 `RestartApplications=yes` 无法稳定重启，再单独设计该扩展。
