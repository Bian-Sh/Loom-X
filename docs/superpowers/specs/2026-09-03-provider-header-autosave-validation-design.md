# Provider 请求头自动保存校验设计

## 目标

修复 Provider 页面新增空白自定义请求头后，自动保存响应重建编辑集合导致空白行自动消失的问题。同时保持自动保存，并避免空名称或空值配置写入设置数据库。

## 方案

- `ProviderEditorViewModel` 将同时维护可编辑的请求头行和可持久化的请求头字典；只有名称和值都非空的完整行才进入 `ProviderInput`。
- 新增或编辑产生的不完整行继续保留在编辑集合中。Provider 保存成功后，服务端响应中的已保存行与当前仍不完整的本地草稿合并；刷新页面时仍以数据库响应为准。
- 自动保存仍按现有防抖流程执行。保存前若存在不完整行，保存有效配置并在 `Status` 与 Warning Toast 中提示待补全数量；空行不会被静默删除。
- 请求头名称和值的完整性校验只影响自定义请求头，不改变 Provider 其他字段的自动保存和请求发送逻辑。

## 数据流与边界

编辑器行变更 -> `HeadersJson` 通知 -> Provider 防抖自动保存 -> 完整请求头字典写入数据库 -> 响应回填已保存行并保留不完整本地草稿。

完全空白的行与只有名称/只有值的行都视为不完整；这些行不写入数据库，也不作为上游请求头发送。重复名称继续沿用现有不区分大小写字典的最后一项覆盖规则。

## 验证

- 空白行添加后集合数量保持不变，自动保存不会清除该行。
- 含不完整行的输入只持久化完整键值，并产生 Warning 状态反馈。
- 完整请求头仍能序列化、回填并用于现有请求路径。
- `dotnet test` 与 `dotnet build OllamaHub.slnx` 通过。
