# AppDataStore 数据中心设计

## 目标

桌面端导航、Provider、网关和活动页面目前会在页面实例创建或刷新时重复读取 SQLite。该设计引入一个由桌面进程持有的 `AppDataStore`，把可复用的运行时数据提升到 MVVM 的 Model 层：启动后后台预加载，页面复用 ViewModel，配置写入数据库后同步替换内存快照，活动使用有界滑动窗口。

控制台是独立的实时日志流，本次不改变 `ConsoleViewModel`、`ConsoleView`、日志缓冲或滚动跟随逻辑。

## 边界与生命周期

- `AppDataStore` 是一个类型和一个实例，不是新增 App、进程或可执行文件。
- `App` 在创建主窗口时创建该实例，并将它注入 `MainWindowViewModel` 及其子 ViewModel；实例生命周期覆盖整个桌面进程。
- 主窗口先显示，数据中心异步初始化。初始化期间页面显示现有风格的加载状态，完成后通过属性变更和事件自动更新。
- 导航只切换已创建的 ViewModel 实例，不重复 `new` Provider、Gateway、Activity、Overview 或 Settings ViewModel。
- 仅在用户明确刷新、编辑保存、活动筛选、活动历史分页等边界访问数据库。普通页面切换只读取内存。

## 配置数据流

### 启动

1. `App` 创建 `ConfigSnapshotService` 和 `AppDataStore`，立即创建主窗口与主 ViewModel。
2. `AppDataStore.InitializeAsync` 在后台加载一次 `ResolvedAppConfig`，并建立 Provider、Model、Gateway Endpoint 的内存快照。
3. 设置页和外观协调使用该快照；初始加载未完成时保留默认外观，快照到达后在 UI 线程应用设置。
4. 初始化成功后发布 `ConfigurationReady`/`ConfigurationChanged`，各 ViewModel 从快照构建展示集合。
5. 初始化失败时保留可重试状态和安全错误摘要，不创建第二份数据库；用户可通过显式刷新重试。

### 读取

`AppDataStore` 提供只读的当前配置快照或按快照派生的 Provider、可用模型、Gateway Endpoint 数据。Provider、Gateway、Overview、Settings ViewModel 不直接创建 DbContext，也不在构造函数中查询数据库。

### 写穿同步

- 所有配置写操作仍通过 `ConfigSnapshotService`/现有管理服务完成，数据库仍是持久化事实源。
- 数据库写入成功后，`AppDataStore` 重新生成一份完整、不可变的 `ResolvedAppConfig`，用一次原子替换更新内存快照，再发布变更事件。
- 页面先根据操作返回值更新局部编辑状态，收到快照变更后统一校正列表、计数、路由和选中项。
- 数据库写入失败时不发布内存成功事件，页面保留编辑内容并显示错误；已有内存快照继续可用。
- `ConfigSnapshotService` 现有文件监视和日志保留，必要时由数据中心触发去抖后的外部变更重载；不记录密钥、正文或 Header 值。

## ViewModel 复用

`MainWindowViewModel` 持有并复用以下实例：

- `OverviewViewModel`
- `ProvidersViewModel`
- `GatewayViewModel`
- `ActivityViewModel`
- 现有 `ConsoleViewModel`
- 现有 `SettingsViewModel`

页面 View 的卸载不能销毁这些长期实例。活动事件订阅在数据中心或主窗口生命周期结束时解除，不能因为 Avalonia 视觉树暂时分离而丢失实时活动。

## 活动数据模型

### 数据源与内存窗口

- `AppDataStore` 订阅 `GatewayProcessService.ActivityEnqueued`，收到事件后先写入既有活动持久化队列，再维护桌面端活动状态。
- “最近活动窗口”最多 500 条，与 ScrollViewer 的可视区域行数无关。
- 最新端模式下，新活动插入窗口头部；超过 500 条时从最旧端淘汰。淘汰只发生在内存，活动数据库仍按现有保留策略保存。
- 历史浏览模式下，新活动不插入当前窗口，只进入待合并计数/缓冲；不改变用户当前选中项和滚动位置。

### 历史分页与滑动窗口

- 活动查询使用 `(CreatedAt, Id)` 复合游标，按时间倒序稳定分页，避免 `OFFSET` 在实时写入时跳项。
- 初始加载取最近 500 条；筛选改变后从第一页开始。
- 用户在列表底部继续上拉时显示回弹加载区和旋转刷新图标，越过阈值后自动加载下一页并追加更旧记录。
- 若筛选结果不足以填满可视区域，自动连续请求下一页，直到填满视口或数据库没有更多匹配记录。
- 滑动窗口始终最多 500 条：追加更旧页导致超限时，从最新端移除相同数量，窗口向历史方向平移；删除的是内存引用，不删除数据库记录。
- 加载期间防重复请求；失败时保留已显示数据，收起加载区并允许下一次上拉重试。
- 没有更多数据时保留明确的结束状态，不再重复触发数据库查询。

### 筛选与返回最新

- 搜索、状态、协议任一条件变化都会清除当前选中项、将列表回到顶部、重置游标和历史模式，并从数据库按筛选条件加载；页面不因首批结果少而显示错误空白。
- 历史浏览期间有新活动时显示轻量的“有 N 条新活动”提示，不抢焦点、不自动滚动。
- 用户点击提示后列表回到最新端，合并待合并活动，重建最近 500 条窗口并清除提示；回到最新端的动作由 View 层保持当前 ScrollViewer 状态后再更新集合，避免跳动。
- 用户本来处于最新端时，新活动直接进入窗口；筛选条件不匹配时只更新待合并计数，不改变当前结果。

## ScrollViewer 交互

活动列表的 `ScrollViewer` 增加独立的尾部加载区和代码后置滚动协调：

- 读取 `Offset`、`Extent`、`Viewport` 判断是否到达底部。
- 在底部继续向上拖动时累计拉伸距离，按阈值显示刷新图标；释放后触发数据中心的历史页命令。
- 加载区高度由拉伸距离限制在稳定范围内，不能挤压或重排右侧详情面板。
- 筛选重置或返回最新完成后，View 将 ScrollViewer Offset 设置到顶部；数据更新期间不修改控制台的任何滚动逻辑。

## 错误处理与并发

- 初始化、配置刷新、活动分页均使用可取消异步操作，避免阻塞 Avalonia UI 线程。
- 配置快照替换和活动窗口替换在单一协调锁下完成，事件发布使用已完成的快照，避免页面看到半更新状态。
- 活动实时事件与历史分页以 `(CreatedAt, Id)` 去重；同一记录不会因分页和实时通知重复显示。
- 数据库暂时不可用时记录结构化日志并显示安全摘要；不把 API Key、Authorization、Header、请求/响应正文或 prompt 放入日志或 Toast。
- 关闭应用时先停止网关和活动订阅，再释放数据中心、数据库监视器和日志工厂。

## 验证范围

### 单元测试

- `AppDataStore` 初始化只执行一次配置加载，重复调用返回同一任务/结果。
- 配置写入成功后发布新快照；失败时快照不变。
- MainWindow 导航反复切换时 ViewModel 引用保持不变，控制台引用和行为不变。
- 活动窗口插入、500 条淘汰、历史平移、实时待合并、返回最新和 `(CreatedAt, Id)` 去重。
- 筛选结果不足一页时自动补齐视口，游标耗尽时正确显示空/结束状态。

### 视图契约与手动验证

- 活动 View 契约测试覆盖尾部加载区、旋转图标绑定、提示回到最新命令和 ScrollViewer 事件处理。
- Provider/Gateway 页面契约测试确认只绑定数据中心状态，不在导航路径调用数据库查询。
- 运行桌面项目构建和相关测试；启动应用后验证窗口先出现加载状态，配置完成后 Provider/Gateway 自动显示，活动上拉分页不影响控制台。

## 非目标

- 不修改活动数据库的保留天数、最大行数或写入批处理策略。
- 不修改网关协议、Provider 数据结构或设置数据库路径。
- 不重写控制台日志缓冲、清空、滚动跟随和实时显示逻辑。
