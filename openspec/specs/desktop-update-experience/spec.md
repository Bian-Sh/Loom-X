# desktop-update-experience Specification

## Purpose
为 Loom-X 桌面端提供低打扰、可持续感知且需要用户最终确认的更新体验，并让用户能够在设置页浏览多个正式版本的完整 Release Notes。

## Requirements

### Requirement: 自动检查后准备更新包

当自动检查更新已启用时，系统 MUST 在启动后和既定周期内检查正式版本；发现高于当前版本且具备兼容安装资产的版本后，系统 SHALL 自动下载并校验更新包，但 MUST NOT 在用户确认前启动安装器。手动检查 MUST 复用同一更新状态，且 MUST 避免并发执行重复检查或重复下载。

#### Scenario: 启动后发现新版本
- **WHEN** 自动检查已启用，应用启动检查到高于当前版本的正式 Release
- **THEN** 系统自动进入下载与校验流程，并保留用户继续使用应用的能力
- **AND** 校验完成后进入等待用户安装确认的状态

#### Scenario: 没有可用更新
- **WHEN** 自动或手动检查未发现高于当前版本的正式 Release
- **THEN** 系统保持当前版本，不显示持久更新入口
- **AND** 手动检查向用户反馈当前已是最新版本

#### Scenario: 重复触发检查
- **WHEN** 检查或下载仍在进行时，定时器或用户再次触发检查
- **THEN** 系统复用正在进行的更新流程，不创建并行的重复网络请求或下载任务

### Requirement: 标题栏提供持久更新状态入口

当存在正在准备、已准备或准备失败的更新时，系统 MUST 在窗口控制按钮左侧显示紧凑的更新状态入口。入口 MUST 默认以图标为主，并在指针悬停时展示版本与当前状态文字；用户关闭更新浮窗后，入口 MUST 保持可用，直到更新完成或不再适用。

#### Scenario: 下载期间查看状态
- **WHEN** 更新包正在下载
- **THEN** 标题栏入口显示下载状态
- **AND** 用户悬停后可以看到目标版本和当前下载百分比

#### Scenario: 更新准备完成
- **WHEN** 更新包下载和校验均已完成
- **THEN** 标题栏入口以可识别的就绪状态持续显示
- **AND** 用户点击入口可以重新打开更新浮窗

#### Scenario: 更新准备失败
- **WHEN** 下载或校验失败
- **THEN** 标题栏入口显示非阻塞的失败状态
- **AND** 用户可以通过入口打开浮窗查看安全错误摘要并重试

### Requirement: 更新浮窗直接呈现说明和操作

用户点击标题栏更新入口时，系统 SHALL 打开符合当前主题的扁平化更新浮窗，并在浮窗内直接渲染目标版本的完整 Markdown Release Note。浮窗 MUST 根据更新状态显示进度或安装操作，且关闭浮窗 MUST NOT 取消后台下载。

#### Scenario: 下载未完成时打开浮窗
- **WHEN** 用户在更新包下载期间打开更新浮窗
- **THEN** 浮窗显示目标版本的 Release Note、已下载字节数、总字节数、速度、百分比和进度条
- **AND** 用户可以选择“稍后”关闭浮窗，下载继续进行

#### Scenario: 校验期间打开浮窗
- **WHEN** 安装包已下载完成但校验尚未结束
- **THEN** 浮窗保留 Release Note，并明确显示正在校验的非确定进度状态

#### Scenario: 更新已准备完成
- **WHEN** 安装包已通过校验
- **THEN** 浮窗显示“稍后”和“重启并安装”操作
- **AND** 只有用户选择“重启并安装”后系统才启动安装器

### Requirement: 设置页浏览正式版本 Release Notes

设置页“更新”Tab MUST 保留当前版本、自动检查、更新代理和手动检查功能，并 SHALL 新增正式版本 Release Notes 浏览板块。系统 MUST 默认加载最近 10 个非 Draft、非 Pre-release 版本，默认选中最新版本，允许切换版本，并允许按页加载更多。

#### Scenario: 首次进入更新页面
- **WHEN** 用户首次进入设置页“更新”Tab
- **THEN** 系统加载最近 10 个正式版本并选中最新版本
- **AND** 最新版本标记为“最新”，与本机版本相同的条目标记为“当前”

#### Scenario: 切换历史版本
- **WHEN** 用户在版本列表中选择另一个已加载版本
- **THEN** 右侧阅读区立即显示该版本的完整 Markdown Release Note
- **AND** 系统不因版本切换重复请求已经缓存的内容

#### Scenario: 加载更多版本
- **WHEN** 用户在版本列表底部选择“加载更多”
- **THEN** 系统在保留当前选中版本和正文的同时追加下一页正式版本

### Requirement: Release Notes 状态与内容安全

Release Notes 浏览板块 MUST 提供加载、空、失败和正常状态。刷新失败时，系统 MUST 保留已有缓存内容并只显示安全错误摘要。Markdown 展示 MUST NOT 执行脚本或加载任意嵌入内容；外部链接仅可通过系统浏览器打开受支持的 HTTPS 地址。

#### Scenario: Release 历史为空
- **WHEN** Release API 返回的结果中没有可展示的正式版本
- **THEN** 设置页显示明确空态并保留刷新操作

#### Scenario: 刷新已有内容时失败
- **WHEN** 设置页已经展示缓存的版本历史，随后刷新请求失败
- **THEN** 已有版本列表和当前正文保持可用
- **AND** 页面显示不包含响应正文、凭据或敏感请求信息的错误摘要与重试操作

#### Scenario: Release Note 包含不安全嵌入内容
- **WHEN** Release Note 中包含脚本、任意 HTML 嵌入或非 HTTPS 外部目标
- **THEN** 展示层不执行或加载这些内容
- **AND** 普通 Markdown 文本、列表、标题、代码和安全链接仍可阅读

### Requirement: 更新网络请求遵循既有代理与发布契约

版本检查、Release 历史拉取和安装包下载 MUST 遵循用户现有的更新代理设置。系统 MUST 继续校验安装器和 SHA-256 资产的兼容命名与内容，不得因 Release Notes 浏览绕过受信任主机或敏感日志约束。

#### Scenario: 更新代理已启用
- **WHEN** 用户配置更新请求使用代理
- **THEN** 版本检查、Release 历史拉取和安装包下载均通过该代理执行

#### Scenario: Release 缺少兼容安装资产
- **WHEN** 正式 Release 没有符合当前发布契约的安装器或校验文件
- **THEN** 该 Release 可以在历史说明中展示
- **AND** 系统不得将其作为可自动安装的更新包

### Requirement: 更新说明浮层保持可读并支持分组折叠

更新说明浮层 MUST 覆盖整个应用内容区域，并相对于整个主窗口居中。遮罩 MUST 始终使用纯黑且 alpha 为 `0.65`，不得随透明主题、窗口透明度或模糊度变化。透明模式下浮层内容 MUST 使用独立磨砂材质并维持足够的不透明度；非透明模式下 MUST 使用对应的实色回退。GitHub Release 正文中的 `🐞 修复问题`、`✨ 新增功能`、`🚀 优化改进` 二级标题 SHALL 投影为默认展开、可折叠的模块，并继续使用安全 Markdown 渲染。

#### Scenario: 透明模式查看更新说明
- **WHEN** 用户在透明模式下打开更新说明
- **THEN** 背景应用内容仍可透过固定 65% 黑色遮罩辨认
- **AND** 更新说明容器具有独立磨砂效果且正文清晰可读
- **AND** 容器相对于整个应用窗口居中，而不是仅在右侧内容面板居中

#### Scenario: 分组浏览 Release Notes
- **WHEN** Release 正文包含 `🐞 修复问题`、`✨ 新增功能`、`🚀 优化改进` 二级标题
- **THEN** 三个标题分别成为 Foldout Header
- **AND** 三个模块默认全部展开，并允许用户独立折叠或展开
- **AND** 模块正文来自 GitHub Release API 返回的正文并继续经过 Markdown 安全策略

#### Scenario: 打开 GitHub 发布页
- **WHEN** 用户点击更新说明右上角的“前往发布页”
- **THEN** 系统使用默认浏览器打开当前 Release 的 HTTPS 发布页
- **AND** 该按钮不关闭更新说明或启动安装器

### Requirement: 就绪更新使用应用内安装确认

更新包完成下载和校验后，用户点击标题栏就绪入口或更新说明中的安装操作时，系统 MUST NOT 再次打开或重新打开 Release Notes 浮层，而 MUST 在当前应用窗口内部显示通用确认模态框。确认内容 MUST 告知应用将退出并重启、路由服务会短暂中断、进行中的请求可能失败；只有用户明确确认后才可启动安装器。

#### Scenario: 就绪入口请求安装
- **WHEN** 更新包已准备完成且用户点击标题栏更新入口
- **THEN** 系统不打开 Release Notes 浮层
- **AND** 系统显示应用内安装风险确认模态框

#### Scenario: 用户取消安装
- **WHEN** 安装风险确认模态框正在显示且用户选择取消
- **THEN** 系统不启动安装器、不退出应用
- **AND** 更新保持 Ready，标题栏入口继续可用

#### Scenario: 用户确认安装
- **WHEN** 安装风险确认模态框正在显示且用户选择确认安装
- **THEN** 系统只启动一次已校验的安装器并请求应用正常退出
- **AND** 路由服务、数据库和日志仍通过现有退出路径释放

### Requirement: 安装器始终创建桌面快捷方式

Windows 安装器 MUST 在安装完成后为当前用户创建 LoomX 桌面快捷方式，不依赖默认未选中的可选任务。

#### Scenario: 完成安装
- **WHEN** 用户完成 LoomX 安装或覆盖升级
- **THEN** 当前用户桌面存在指向安装目录 `LoomX.exe` 的快捷方式
