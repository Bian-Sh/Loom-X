# Spec Delta

## ADDED Requirements

### Requirement: 编译缓存身份变化必须可诊断

Runtime SHALL 在源码插件编译缓存未命中时，于结构化日志中明确指出缓存身份各组成部分（引用集摘要、编译器身份、编译选项身份、插件输入）中发生变化的项，MUST NOT 只输出最终缓存键而不提供可定位的变化原因。缓存命中时 SHALL 记录命中事件。

#### Scenario: 宿主更新后未命中可定位原因

- **WHEN** 宿主更新后首次启动，某源码插件缓存未命中
- **THEN** 日志明确指出身份中发生变化的组成部分（如引用集摘要或编译器身份）
- **AND** 未变化的部分同时输出以供对照

#### Scenario: 缓存命中记录事件

- **WHEN** 某源码插件编译缓存命中
- **THEN** 日志记录命中事件与对应插件标识

### Requirement: 宿主常规发布后第一方插件不得重复编译

系统 SHALL 使第一方源码插件的编译产物随宿主发布提供，保证在插件源码与生效编译输入（引用集、编译器、编译选项）未变化时，宿主更新后的首次启动直接复用编译产物而不重新编译。该复用路径 MUST 复用既有缓存完整性与认证机制，MUST NOT 为绕过身份校验引入不受保护的产物加载。用户自建源码插件的运行时编译行为保持不变。

#### Scenario: 宿主更新且插件输入未变化

- **WHEN** 用户安装宿主更新，第一方插件源码与生效编译输入未变化
- **THEN** 更新后首次启动复用随宿主提供的编译产物
- **AND** 不执行重新编译，插件阶段不出现编译耗时

#### Scenario: 插件输入变化仍然重新编译

- **WHEN** 第一方插件源码、Manifest 或生效编译输入发生变化
- **THEN** 系统按既有缓存语义重新编译并生成新缓存身份

#### Scenario: 产物完整性校验失败回退编译

- **WHEN** 随宿主提供的编译产物缺失或完整性校验失败
- **THEN** 系统回退到运行时编译，行为与未提供产物时一致
- **AND** 通过日志记录回退原因

### Requirement: 插件阶段固定开销必须受控

Runtime SHALL 并行编译相互独立的源码插件，且 SHALL 通过结构化日志使插件阶段内各耗时构成（发现、编译、加载、以及宿主服务构建中的编译前置环节）可被测量归属，MUST NOT 让无法归属的固定开销掩盖优化效果。

#### Scenario: 多插件并行编译

- **WHEN** 启动期存在多个相互独立的待编译源码插件
- **THEN** 系统并行执行编译，各插件诊断仍按插件归组输出
- **AND** 插件发现与加载顺序保持既有确定性顺序

#### Scenario: 插件阶段耗时可归属

- **WHEN** 桌面启动插件阶段完成
- **THEN** 日志可区分发现、编译、加载及前置环节的耗时构成
