# 桌面端页面切换性能修复

## 问题

点击控制台导航后，页面通常需要等待 1 到 2 秒才显示。其它包含长列表的页面在数据量较大时也可能出现相同的短暂卡顿。

## 根因

控制台日志最多保留 5000 条，但视图使用非虚拟化 `ItemsControl`，每次导航创建视图时会一次性生成全部日志行。运行期间每条日志到达后，`ConsoleViewModel` 又会清空并重建整个可见集合，重复触发大量布局工作并阻塞 UI 线程。活动页面同样使用非虚拟化长列表。

## 修复目标

- 控制台和活动长列表只为可视区域创建行，首次切换不再按全部记录布局。
- 新日志到达时增量更新可见集合，避免每条日志全量重建。
- 保持筛选、级别计数、滚动跟随、清空和复制行为不变。
