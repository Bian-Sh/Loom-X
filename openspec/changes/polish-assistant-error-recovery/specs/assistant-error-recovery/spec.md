## Purpose

为 AI 助手请求提供有限且安全的自动恢复机制，并确保无法恢复的终态错误在透明主题下以清晰、克制且无多余操作的消息气泡呈现。

## ADDED Requirements

### Requirement: 可恢复模型错误有限自动重试

系统 MUST 对连接失败、模型请求超时、HTTP 408、HTTP 429 和 HTTP 5xx 等可恢复模型错误执行自动重试，并将首次请求计入最多 5 次总尝试次数。

#### Scenario: 瞬时错误随后恢复
- **WHEN** 模型请求在尚未产生可见流式内容前遇到可恢复错误，且后续尝试在第 5 次或之前成功
- **THEN** 系统继续当前助手轮次，不要求用户手动重试，也不重复追加用户消息

#### Scenario: 可恢复错误耗尽尝试次数
- **WHEN** 同一步骤连续 5 次请求均以可恢复错误失败
- **THEN** 系统停止重试并产生一条终态失败事件，只展示最后一次错误的安全摘要

#### Scenario: 已产生流式内容后连接失败
- **WHEN** 当前尝试已经产生正文、思考或工具调用内容后发生连接错误
- **THEN** 系统不得自动重放该请求，以避免重复正文或重复工具行为，并将本轮标记为失败

### Requirement: 确定性错误立即失败

系统 MUST 对无效请求、认证失败、权限拒绝、额度不足、模型不存在、上下文超限和内容过滤等确定性错误立即失败，不消耗额外重试次数。

#### Scenario: 额度不足
- **WHEN** Provider 返回 HTTP 402 或可识别的额度不足错误码
- **THEN** 系统只尝试一次并立即产生终态失败事件

### Requirement: 服务端重试等待提示

系统 MUST 在可恢复错误包含有效 `Retry-After` 时优先遵循该等待时间，否则使用有上限的递增退避，并允许用户取消等待。

#### Scenario: 速率限制包含等待时间
- **WHEN** Provider 返回 HTTP 429 且附带有效 `Retry-After`
- **THEN** 下一次尝试在该等待时间后开始，等待期间取消操作立即终止本轮

### Requirement: 终态错误使用专属消息气泡

桌面端 MUST 将终态失败作为消息流中的左对齐异常气泡展示，不提供“重试”或“忽略”按钮。异常气泡 MUST 使用淡红透明表面、细描边、普通字重、较大字号和中性深色正文，并保持足以隔离任意桌面着色源的最低表面不透明度。

#### Scenario: 透明主题显示终态错误
- **WHEN** 助手请求在透明主题下最终失败
- **THEN** 错误详情以可换行的 14px 普通字重异常气泡显示，且背景不会随全局透明度降低到不可读

#### Scenario: 历史会话重放终态错误
- **WHEN** 用户重新载入包含终态失败事件的历史会话
- **THEN** 同一错误仍以异常气泡恢复显示，而不是普通状态文字或独立操作卡片
