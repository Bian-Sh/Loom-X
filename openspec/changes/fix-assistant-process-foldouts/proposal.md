# 修复 AI 助手过程折叠层级与完成时机

## 问题

现有 AI 助手把每个步骤或首个文本增量都当成 `finish_content`，导致同一轮对话产生多个“已完成”过程块；第一轮修复虽然建立了父子 foldout，但 header、hover 和 checked 状态仍过强，完成后仍可能显示动态预览，工具参数与结果也没有投影到界面。

## 根因

`AssistantViewModel.Project` 已修正父过程的完成边界，但子标题只依赖自身展开状态，没有感知父过程完成；`ToggleButton` 的主题伪状态覆盖了透明样式；工具调用的完整参数和结果虽已保存在 assistant/tool `MessageCompleted` 与 JSONL 中，投影层却只消费了安全摘要事件。

## 目标

1. 每轮对话只使用一个过程父 foldout，汇总该轮全部思考与工具调用，并与最终内容处于消息流同级。
2. 最终内容完成前显示“处理中”，只有无工具调用的最终 assistant 消息完整输出后才显示“已完成”并默认折叠。
3. 同一轮只保留“思考”和“工具调用”两个多语言子 foldout；仅处理中且折叠时显示最新内容，完成后固定显示标签。
4. foldout 无背景、无 hover/selected 底色；箭头位于文字后方、仅划入时出现并使用 80% 白色。
5. 每个工具调用可分别展开“调用”参数和“完成/失败”结果，内层入口不显示背景与箭头。
6. 使用不提交、不打包的本地 JSONL Mock 模块覆盖长思考、多工具、成功、失败、拒绝、取消、处理中和已完成场景。

## 规格说明

本次修复收紧已有 AI 助手设计的 UI 投影语义，不新增 OpenSpec capability，因此不创建 delta spec。
