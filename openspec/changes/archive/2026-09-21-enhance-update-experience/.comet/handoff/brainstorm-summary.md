# Brainstorm Summary

- Change: enhance-update-experience
- Date: 2026-09-20

## 确认的技术方案

- 采用单一全局更新协调器管理检查、自动下载、校验、Ready、失败重试和安装确认；Release 历史分页与选择由独立状态模型管理。
- 以小型 `IUpdateService` 契约隔离协调器和历史状态模型需要的 Release 拉取、更新包准备与安装器启动操作，便于使用假实现测试状态机，不引入通用服务框架。
- 将现有“下载并立即启动安装器”拆分为 `PrepareUpdateAsync` 与 `LaunchInstaller`：自动检查只准备并校验安装包，用户点击“重启并安装”后才允许启动安装器。
- 安装确认通过应用级回调或事件交给桌面壳层处理：记录已验证安装器路径、启动安装器并触发应用正常关闭，让既有 Exit 清理网关、数据库与日志；安装器继续沿用 Inno Setup 的 CloseApplications、RestartApplications 与发布资产命名。
- 启动和 24 小时定时检查发现具备兼容安装资产的正式新版本后自动准备；手动检查复用正在执行的检查/准备任务。缺少安装资产的正式 Release 仅进入历史列表，不进入自动安装流程。
- 标题栏在最小化按钮左侧增加专用更新入口；默认仅显示图标，Hover 通过宽度和透明度过渡显示版本、进度或错误摘要。该入口不复用会自动隐藏的 ToastService。
- 点击标题栏入口打开单层扁平更新浮窗；浮窗固定头部和底部操作区，中间直接使用共享 Markdown 视图渲染当前目标 Release Note。下载中显示确定进度，校验中显示非确定进度，Ready 显示“稍后 / 重启并安装”，失败显示重试。
- 设置页更新 Tab 保留现有版本、自动检查、更新代理和手动检查功能；下方增加左侧版本列表与右侧 Markdown 阅读区。首次惰性加载 10 个正式版本，加载更多按页追加并去重，刷新失败保留缓存和当前选择。
- 更新浮窗和设置页复用基于 `LiveMarkdown.Avalonia` 的只读 Release Notes 展示组件；组件只负责内容展示，不持有网络、下载或安装状态。
- 所有用户可见状态写入 zh-CN、zh-TW、en-US 资源；网络和业务日志使用 `ILogger<T>` 记录安全摘要，不记录 Release 正文、请求正文或凭据。

## 关键取舍与风险

- 自动下载会增加网络流量：仅在现有“自动检查更新”开启时自动准备，并继续遵循更新代理设置。
- GitHub 未认证 API 有速率限制：历史页面惰性加载、每页 10 条、会话缓存，版本切换不发请求。
- 当前服务类为 concrete 类型，协调器难以单测：仅为更新域引入窄接口，避免扩展成全项目依赖注入重构。
- 安装器启动与应用退出存在时序风险：只传递已校验路径，由桌面壳层执行一次性安装请求，并测试重复点击不会重复启动。
- Markdown 可能包含 HTML、图片或危险链接：禁用脚本与任意嵌入资源，只允许通过系统浏览器打开 HTTPS 链接；失败时仍展示安全文本内容。
- 透明主题截图不能作为颜色事实源：视觉验证同时覆盖浅色、深色和关闭透明效果的实际控件可读性。

## 测试策略

- `UpdateServiceTests`：分页参数、稳定版过滤、版本映射、兼容资产判定、准备阶段不启动安装器、SHA-256 校验、缓存复验、显式启动安装器。
- `UpdateCoordinatorTests`：自动准备状态路径、并发任务复用、进度与 Ready、稍后不取消、失败重试、重复安装确认幂等。
- Release History ViewModel 测试：首次 10 条、默认选择、当前/最新标记、切换不请求、加载更多追加去重、刷新失败保留缓存、空态。
- AXAML/视图契约测试：标题栏入口位于窗口控制区、旧右下角卡片被移除、浮窗包含共享 Markdown 视图与状态区、设置页保留原控件并增加分栏历史区。
- 本地化与安全测试：资源键覆盖、无硬编码用户可见中文、日志不含 Release 正文、外部链接协议限制。
- 集成验证：Release 构建、相关测试和必要完整测试；CUA 检查标题栏 Hover、浮窗下载/Ready/错误状态、版本切换、三类主题可读性；重新发布到时间命名的 `outputs` 目录。
