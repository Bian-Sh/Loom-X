# 修复交互式 UI 的事件驱动自动保存

## 问题

桌面端文本框在输入过程中仍可能被旧的绑定值回写，随后控件重建或刷新导致输入丢失和焦点丢失。Provider、Settings 还依赖 `DebouncedAutoSaver`，保存时序与绑定回写交叉，连续输入时旧保存结果也可能覆盖新编辑状态。

## 根因

部分 TextBox 使用默认或 `LostFocus` 更新源，用户正在输入时 ViewModel 仍持有旧值；同时属性变化后的防抖保存没有明确的编辑版本边界。数据库快照应用与用户编辑没有统一的“只更新 UI、不触发保存”路径。

## 目标

1. 可编辑控件在用户修改时立即把值写入 ViewModel，避免旧值回写和不必要的控件重建。
2. 用户编辑事件直接触发串行自动保存，不再使用 `DebouncedAutoSaver` 协调配置页面保存。
3. 数据库加载和保存响应只能更新 UI/保存标记，不能再次触发保存；连续输入时旧响应不能清除较新的脏状态。
4. Gateway、Providers、Settings 的可交互控件保持一致，并有契约测试覆盖。
