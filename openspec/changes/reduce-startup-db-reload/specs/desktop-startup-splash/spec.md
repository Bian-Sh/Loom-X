# Spec Delta

## MODIFIED Requirements

### Requirement: 启动初始化必须避免重复读库

系统 SHALL 在一次启动过程中以一次配置库读取结果构造启动所需的完整配置快照，MUST NOT 在同一启动流程内重复打开、重复初始化或重复加载同一配置库来组装同一份快照。该约束 SHALL 覆盖整个启动流程：从配置库首次初始化起，到主窗口初始化完成（Shell 阶段结束）止，包括 Providers 页面首刷与 AI 助手首次模型摘要在内的所有启动期数据消费 MUST 复用该快照或其内存状态。仅当出现用户显式刷新操作或非本机保存的配置变更事件时，系统才 SHALL 允许重新读库。

#### Scenario: 配置库只加载一次

- **WHEN** 桌面启动需要读取配置数据库
- **THEN** 系统只执行一次配置库初始化与快照读取
- **AND** 后续启动阶段（含 Shell 阶段的页面首刷与助手模型摘要）复用该快照构造主窗口状态

#### Scenario: 启动阶段仍然可见

- **WHEN** 配置数据库初始化与读取完成
- **THEN** 闪屏把配置数据库阶段标记为完成
- **AND** 系统继续进入插件或网关相关阶段

#### Scenario: 主界面初始化不读库

- **WHEN** Shell 阶段执行主窗口初始化、Providers 页面首刷与助手首次模型摘要
- **THEN** 系统不再打开或初始化配置数据库
- **AND** 页面与助手展示的数据与启动快照一致

#### Scenario: 显式刷新仍可读库

- **WHEN** 用户在 Providers 页面执行刷新操作，或到达非本机保存的配置变更事件
- **THEN** 系统允许重新读取配置数据库并更新内存状态

## ADDED Requirements

### Requirement: 启动读库次数必须可验证

系统 SHALL 通过自动化回归测试证明整个启动流程内配置库只被初始化与读取一次，且该测试 SHALL 覆盖「编排器 Database 阶段 → Shell 阶段 → 主窗口初始化完成」的完整链路。测试 SHALL 同时验证显式刷新路径仍能按需读库，防止为消除重复读库而破坏刷新语义。

#### Scenario: 启动链路读库一次

- **WHEN** 自动化测试模拟完整启动链路（编排器初始化 + Shell 阶段主窗口初始化）
- **THEN** 配置库初始化/读取恰好发生一次
- **AND** 后续阶段消费的数据与该次读取结果一致

#### Scenario: 显式刷新读库不受限

- **WHEN** 自动化测试在启动完成后触发显式刷新或配置变更事件
- **THEN** 系统按需重新读库并更新内存状态
- **AND** 该读取不计入启动流程的一次读库约束

#### Scenario: 日志可诊断读库行为

- **WHEN** 桌面启动完成
- **THEN** 日志中配置库初始化相关条目在整个启动流程内只出现一次
- **AND** 出现计划外的第二次初始化时可通过日志直接定位触发方
