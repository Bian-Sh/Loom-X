## Purpose

规范 AI 助手聊天页中标题操作区、消息滚动、消息输入与模型选择弹层的可见布局和交互，使界面在不同窗口高度下保持清晰、紧凑且不遮挡消息内容。

## ADDED Requirements

### Requirement: 标题操作与消息滚动条对齐

桌面端 MUST 使新会话按钮的图标中心与消息区纵向滚动条中心处于同一垂直轴线，并保持历史会话按钮与新会话按钮之间存在清晰间距。

#### Scenario: 默认窗口尺寸下显示标题操作区

- **WHEN** 用户以默认窗口尺寸打开 AI 助手页
- **THEN** 新会话图标中心与消息区纵向滚动条中心对齐，且不会紧贴历史会话图标

### Requirement: 消息滚动条避让对话内容

消息区纵向滚动条 MUST 在指针悬停时向窗口右侧扩张，不得向左覆盖或挤压用户对话气泡。

#### Scenario: 悬停消息区滚动条

- **WHEN** 用户将指针移到消息区纵向滚动条上
- **THEN** 滚动条 Thumb 从左侧基准向右侧变宽，消息内容区域保持不变

### Requirement: 输入框按内容自动增高

消息输入框 MUST 支持多行自动换行并随内容增高，最大高度为应用客户区高度的 32%；达到最大高度后 MUST 在输入框内部提供纵向滚动，并保持 Enter 发送、Shift+Enter 换行。

#### Scenario: 输入少量多行内容

- **WHEN** 用户输入的内容高度低于应用客户区高度的 32%
- **THEN** 输入框随内容自然增高且不显示不必要的内部滚动条

#### Scenario: 输入内容超过高度上限

- **WHEN** 用户输入的内容高度超过应用客户区高度的 32%
- **THEN** 输入框停止增高并显示内部纵向滚动条以查看其余内容

#### Scenario: 使用键盘换行和发送

- **WHEN** 用户按 Shift+Enter
- **THEN** 输入框插入换行且不发送消息
- **WHEN** 用户单独按 Enter
- **THEN** 当前消息被发送

### Requirement: 模型选择弹层保持紧凑比例

模型选择弹层 MUST 使用 296px 宽度和 360px 最大高度，并使用紧凑的搜索框、Provider 标题行与模型行，同时保持搜索、模型列表与思考等级控件完整可用。

#### Scenario: 打开模型选择弹层

- **WHEN** 用户点击输入区的模型选择按钮
- **THEN** 弹层以 296px 宽度打开，内容超过 360px 时模型列表可滚动且底部思考等级控件仍可见
