# 修复设计

首实例获取 `Local\\LoomX` 互斥锁后启动用户会话内的命名管道监听器。监听器只接受固定的 `activate` 命令，并在 `App` 释放时停止。管道处理不参与配置库或网关初始化，因此激活通道故障不会影响首实例。

后续实例获取不到互斥锁时，以短超时重试连接监听器，发送 `activate` 后记录发送结果并退出。未连接成功时只记录告警，不创建第二套配置库、网关或 UI。

主窗口暴露内部激活方法，由 UI dispatcher 执行：若窗口最小化则恢复，调用 Avalonia `Activate()`；Windows 平台通过窗口句柄调用 `ShowWindow(SW_RESTORE)` 和 `SetForegroundWindow`，其他平台保留 Avalonia 标准行为。激活操作幂等，不改变当前页面或配置。

纯协议和重试逻辑保持可单元测试；窗口前置通过发布包双启动验收验证。所有日志使用结构化模板，只记录进程标识、发送/接收结果和耗时，不记录管道正文以外的用户数据。
